# Contributing to MCG Signal

These rules apply to each repository of this organization. They keep the history of a repository short and easy to read.

1. **Do not push to `main`.** Make a branch and open a pull request. `main` refuses a direct push.
2. **One pull request has one change.** We merge it as one squash commit. The title of the pull request becomes the commit message on `main`.
3. **Write the title as `<type>: <what changed>`.**
   - Each repository can use the types `docs` (only the text changes) and `repo` (the settings, templates or other files of the repository change). A repository lists its other types in its README.
   - Start with a verb in the present tense: add, change, remove, move.
   - Use lower case after the colon, no full stop at the end, and 72 characters or fewer.
   - Write in ASD-STE100 Simplified Technical English: approved words, active voice, short sentences.
   - Examples: `docs: add an example to the burn method`, `repo: add the form for data errors`.
4. **Write the description in three parts: Problem, Change, Proof.** The proof is a test result, a transaction hash, a block number or a link that anyone can check.
